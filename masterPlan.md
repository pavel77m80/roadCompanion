# Road Companion — мастер-план рабочего сервиса

Road Companion — приложение-компаньон автопутешествий: во время поездки на
смартфоне проигрываются короткие исторические, культурные и природные рассказы
о местах, мимо которых едет автомобиль. Контент готовится заранее из открытых
источников, а воспроизведение работает без обязательной сети.

Документ описывает целевой сервис, его архитектуру, принципы приватности и
данных, MVP и дорожную карту. Предыдущие исследовательские прототипы (маршруты,
POI-подбор, полевые проверки GPS) служили только доказательством концепции;
личные маршруты и координаты поездок в репозиторий не входят.

## 1. Назначение и пользовательский сценарий

- Пользователь планирует автомобильную поездку задаёт маршрут (или использует
  текущую поездку).
- Сервис заранее подбирает вдоль маршрута интересные объекты и готовит короткие
  рассказы (30–90 секунд) с фактами из проверяемых источников.
- Во время движения GPS определяет приближение к объекту; рассказ проигрывается
  без отправки данных в сеть в момент проезда.
- История повторно не воспроизводится; при съезде с маршрута триггеры временно
  отключаются, при возвращении — включаются снова.
- При потере сети базовые истории продолжают работать (офлайн-бандл на устройстве).

## 2. Целевая архитектура

```
┌─────────────────────────── Android-устройство ─────────────────────────────┐
│ маршрут → серверный/фоновый подбор POI → подготовка контента → офлайн-бандл │
│ GPS (foreground) → GPS-движок → триггер истории → TTS/аудио + карточка       │
│ диалог пассажира → контекст POI + источники → ответ                          │
└───────────────────────────────────────────────────────────────────────────────┘
```

Компоненты:

- **GPS playback engine** (`offline_pack/companion_core/playback.py`) —
  определяет приближение к POI: фильтр точности, телепорт-фильтр, отслеживание
  съезда с маршрута, однократность триггера, сериализация состояния.
- **Офлайн-бандл** (`bundle.py`, `build_bundle.py`) — локальный пакет маршрута,
  историй и источников. Ядро не использует сеть (проверяется тестами).
- **Контент-пайплайн** — геокодирование, построение маршрута (OSRM / ORS),
  поиск POI (Overpass), обогащение (Wikidata/Wikipedia), генерация карточек.
- **Полевая проверка GPS** (`offline_pack/field/`) — инструменты записи трека,
  импорта, replay и метрик качества для проверки движка на реальном железе.
- **UI и озвучка** — мобильное приложение (Android), текстовые карточки,
  синтез речи, обработка вопросов пассажира.

## 3. Принципы данных и приватности

Обязательные правила сервиса:

- Не собираем и не публикуем персональные данные: адреса, домашние координаты,
  поездки и их треки.
- Личные маршруты и сырые GPS-треки не попадают в репозиторий; допускаются
  только агрегированные метрики и нейтральные синтетические данные.
- Источники контента — открытые данные: OpenStreetMap (ODbL), Wikipedia
  (CC BY-SA), Wikidata (CC0). Атрибуция сохраняется в бандле.
- Факты отделяются от интерпретаций и гипотез; неподтверждённые сведения в
  рассказы не включаются.
- Секреты (ключи API) не сохраняются в репозитории, отчётах и логах.

## 4. Технологический стек (рекомендуемый)

Бесплатные/открытые компоненты, проверенные в исследовании:

- маршрутизация: **OSRM** (публичный demo для прототипа; для production —
  самостоятельное развёртывание) или **openrouteservice** (бесплатный тариф
  требует ключ `ORS_API_KEY`);
- POI: **Overpass API** (OpenStreetMap);
- факты: **Wikidata / Wikipedia API**;
- ядро: Python 3.10+ (стандартная библиотека; без сетевых модулей в движке);
- приложение: Android (Kotlin), фоновое местоположение в foreground-сервисе.

## 5. Статусы проверок

Каждый результат разработки/исследования имеет статус:
`PASS`, `FAIL`, `BLOCKED` или `NOT_RUN`.

## 6. Этап 1: Ядро и офлайн-бандл (MVP)

Критерий: воспроизводимый офлайн-сценарий истории вдоль произвольного маршрута.

- [x] GPS playback engine: точность, телепорт-фильтр, съезд/возврат, однократность.
- [x] Офлайн-бандл: схема 1.0.0, валидация, атрибуция источников, без сети.
- [x] Воспроизводимая симуляция поездки (синтетические GPS-фиксации).
- [x] Полевые инструменты GPS: рекордер, импорт (GPX/NMEA/JSON), replay, метрики,
      калибровка параметров.
- [x] Тесты (unittest): ядро, бандл, отсутствие сетевых вызовов, полевые инструменты.
- [ ] Переиспользуемый контент-пайплайн для произвольного маршрута (без
      привязки к личному маршруту).

## 7. Этап 2: Контент-пайплайн как сервис

- [ ] Абстракция «маршрут»: входные адреса/точки вместо фиксированного маршрута.
- [ ] Пайплайн: геокодирование → маршрут → коридор POI → дедупликация →
      расстояние вдоль маршрута → обогащение Wikidata/Wikipedia → карточки.
- [ ] Кэш запросов и режим обновления без дублирования обращений к API.
- [ ] Валидация POI: только объекты с подтверждёнными фактами и источниками.
- [ ] Генерация офлайн-бандла из карточек (схема 1.0.0).

## 8. Этап 3: Мобильное приложение

- [ ] Android: получение маршрута, загрузка бандла, foreground-GPS-сервис.
- [ ] Воспроизведение историй (TTS), карточка объекта, однократные триггеры.
- [ ] Офлайн-работа: базовые истории без сети.
- [ ] Обработка вопросов пассажира с контекстом POI и ссылками на источники.
- [ ] Проверка политик Google Play и Android for Cars.

## 9. Этап 4: Production-готовность

- [ ] Самостоятельное развёртывание маршрутизатора (OSRM/ORS) и контент-сервиса.
- [ ] Учёт лимитов и лицензий открытой инфраструктуры при росте аудитории.
- [ ] Метаданные провенанса контента, автообновление бандлов.
- [ ] Телеметрия только агрегированных метрик без персональных данных.

## 10. Метрики качества

- Доля POI с подтверждёнными источниками (цель: > 80% включённых).
- Доля объектов с рассказом при проезде в радиусе (полевая проверка).
- Отсутствие повторных триггеров и ложных срабатываний (журнал событий).
- Офлайн-работа: срабатывания без сетевых запросов движка (тесты).
- Приватность: отсутствие личных маршрутов/треков в репозитории (проверка git).
